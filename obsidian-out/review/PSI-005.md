## 3. Key Decisions & Rationale

| Decision | Rationale | Alternatives Considered |
|---|---|---|
| `graphify install --project` instead of `graphify claude install` first | The `--project` flag installs the skill into `.claude/skills/` plus the CLAUDE.md section AND the PreToolUse hooks in one shot — it subsumes `graphify claude install` | Running `claude install` then `--project` separately (redundant; --project already does both) |
| Graphify rules in both CLAUDE.md and AGENTS.md | Claude Code reads CLAUDE.md for always-on rules; Hermes reads AGENTS.md via `.hermes.md` — both agents need the same graph-first navigation policy | Putting it only in one file (the other agent would miss it) |
| `.graphifyignore` already excluded `graphify-out/` from graph self-indexing | Prevents circular dependency — graphify shouldn't try to index its own output | Re-including graphify-out (waste of tokens, no signal) |
| Snapshot dated `2026-09-25_phase-0` follows existing convention | Matches the pattern in `docs/graphify-architecture/README.md`: snapshots named by date and phase | Using `PSI-005` as suffix (phase-level is more useful as the project evolves) |
