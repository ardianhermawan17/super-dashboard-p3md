# MCP Client Compatibility: DCR vs CIMD (PSI-078)

> **Scope:** Verification and setup guide for external Model Context Protocol (MCP) clients (Claude Desktop, ChatGPT, Hermes Agent, Cursor) connecting to P3MD via Supabase OAuth 2.1 server.
> **Related:** [agent-layer-mcp.md](agent-layer-mcp.md) · [auth-and-onboarding.md](auth-and-onboarding.md) · [operations-and-risks.md](operations-and-risks.md)

## 1. Executive Summary

| Client | Auth Mechanism | Supabase Compatibility | Configuration Mode | Status |
|---|---|---|---|---|

## 2. DCR (Dynamic Client Registration) vs CIMD (Client ID Metadata Documents)

### What is DCR (RFC 7591)?
Dynamic Client Registration is the standard OAuth 2.0 mechanism where a client discovers the authorization server's `registration_endpoint` and submits a JSON payload to register itself at runtime:
```http
POST /auth/v1/oauth/clients/register
Content-Type: application/json
apikey: <SUPABASE_ANON_KEY>

{
  "client_name": "Claude Desktop",
  "redirect_uris": ["http://127.0.0.1:3000/auth/callback"],
  "grant_types": ["authorization_code"],
  "response_types": ["code"],
  "token_endpoint_auth_method": "none",
  "scope": "openid profile email"
}
```
Supabase GoTrue responds with:
```json
{
  "client_id": "338350cd-4c1c-4888-ab55-2001d381e254",
  "client_name": "Claude Desktop",
  "redirect_uris": ["http://127.0.0.1:3000/auth/callback"],
  "grant_types": ["authorization_code"],
  "response_types": ["code"],
  "token_endpoint_auth_method": "none",
  "scope": "openid profile email"
}
```

### What is CIMD (draft-ietf-oauth-client-id-metadata-document)?
In draft MCP specifications (2025/2026), **Client ID Metadata Documents (CIMD)** allow a client to use an HTTPS URL as its `client_id` (e.g. `client_id=https://claude.ai/oauth/mcp-client.json`). The authorization server fetches the JSON document directly without requiring an upfront registration call.

### Supabase GoTrue Assessment:
1. Supabase Auth (GoTrue) advertises `registration_endpoint: .../oauth/clients/register` in its RFC 8414 metadata.
2. Supabase GoTrue currently expects `client_id` to be a registered UUID in its internal database table (`oauth_clients`).
3. If an MCP client passes an unregistered HTTPS URL directly as `client_id`, GoTrue responds with `400 invalid_client` / `oauth_authorization_not_found`.
4. **Workaround / Resolution:** All major clients (Claude Desktop, Hermes Agent) fallback to or natively support RFC 7591 DCR when `registration_endpoint` is advertised in `/.well-known/oauth-authorization-server`.

## 3. Client-by-Client Setup Guide

### 3.1 Claude Desktop
Claude Desktop automatically discovers endpoints from the server's protected resource / authorization server metadata:
1. In `claude_desktop_config.json`:
```json
{
  "mcpServers": {
    "p3md": {
      "url": "https://<your-domain>/api/mcp",
      "transport": "sse"
    }
  }
}
```
2. Claude discovers `https://<ref>.supabase.co/auth/v1/.well-known/oauth-authorization-server`.
3. Claude registers dynamically via DCR, prompts the user in browser on `/auth/consent`, and stores the issued token locally.

### 3.2 ChatGPT (Custom Actions & MCP)
ChatGPT Actions require static OAuth parameters:
- **Authorization URL**: `https://<ref>.supabase.co/auth/v1/oauth/authorize`
- **Token URL**: `https://<ref>.supabase.co/auth/v1/oauth/token`
- **Client ID & Secret**: Generated by running a one-time DCR script or configured in Supabase Dashboard (Auth → OAuth Apps).
- **Scope**: `openid profile email`

### 3.3 Cursor (IDE Assistant)
For Cursor's MCP configuration (`.cursor/mcp.json` or Settings → Features → MCP):
```json
{
  "mcpServers": {
    "p3md": {
      "url": "http://127.0.0.1:3000/api/mcp",
      "headers": {
        "Authorization": "Bearer <USER_SUPABASE_JWT>"
      }
    }
  }
}
```
Cursor sends the token in the `Authorization: Bearer <token>` header, which `src/agent/auth.ts` verifies against Supabase JWKS.

### 3.4 Hermes Agent / Custom CLI
Hermes Agent uses `@modelcontextprotocol/sdk` with DCR PKCE:
- Client registration: `POST /auth/v1/oauth/clients/register`
- Authorization: `GET /auth/v1/oauth/authorize?client_id=...&code_challenge=...&code_challenge_method=S256`
- Token exchange: `POST /auth/v1/oauth/token` with `grant_type: "authorization_code"`

## 4. Security & Revocation

- All issued tokens contain the standard Supabase user payload:
  - `sub`: User UUID
  - `role`: `authenticated`
  - `client_id`: OAuth Client UUID
  - `scope`: Granted scope list (`openid profile email`)
- Row-Level Security (RLS) policies evaluate against `auth.uid()`.
- Users can view all authorized clients and revoke access anytime at `/dashboard/connected-apps` (PSI-075).
