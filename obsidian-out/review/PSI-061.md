## 1. Feature Summary & Goal

- **Objective:** Implement PostgreSQL migration M6 establishing tables, security policies, triggers, and service functions for Google Drive document mirroring and Google Calendar bidirectional synchronization.
- **Components:**
  - `drive_roots`: Root Drive folders shared with the Service Account.
  - `drive_root_access`: Granular access mapping by `role_id` or `group_id` (mutually exclusive XOR check constraint).
  - `drive_files`: Mirror of synced files with GIN trigram index on `name` for high-performance substring searches.
  - `document_views`: Immutable audit log tracking which user accessed or streamed which document.
  - `google_calendars`: Linked Google calendar configurations (`pull`, `push`, `both`) with role/group targets.
  - `event_google_links`: Mapping between internal app `events` and remote Google calendar event IDs.
  - Security Definer Helpers & RLS: `can_see_drive_root(uuid)` enforcing permission/role/group hierarchy; RLS on all 6 tables.
  - Push Triggers: `events_google_push`, `events_google_delete`, and `audience_google_push` dispatching async Edge Function jobs via `public.internal_post`.
  - Service-Role Functions: `upsert_google_event(...)` and `prune_google_events(...)` for transactional sync workers.
  - pg_cron: Automated recurring cron schedules for `google-drive-sync` (every 30m) and `google-calendar-sync` (every 15m).
