- **Objective:** Add the Supabase browser/server clients plus a session-refresh proxy so the dashboard is behind authentication — unauthenticated visits redirect to `/auth/sign-in`, while public endpoints (`/api/mcp`, `/sw.js`, `/manifest.webmanifest`, etc.) stay reachable.

## 3. Key Decisions & Rationale

| Decision | Rationale | Alternatives Considered |
|---|---|---|
| Install `@supabase/ssr` + `@supabase/supabase-js` | Doc imports them; template had neither | Hand-rolled fetch wrappers |
| `PUBLIC_PREFIXES` = union of accept + doc lists | Satisfies both contract and design docs | Only 3 accept-listed prefixes (breaks auth/calendar/push) |
| `getClaims()` for session read | Recommended by ssr docs; avoids extra user round-trip | `getSession()` + `getUser()` |
