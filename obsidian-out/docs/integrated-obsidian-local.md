# Integrated Obsidian (local)

> A local Obsidian vault that shows the task list as a live Kanban board and dumps every AI session into a browsable work log. Generated by `scripts/obsidian-sync.ts` into `obsidian-out/`.
> Sources: [list-task-project.md](list-task-project.md) · [historical-agent-work.md](historical-agent-work.md) · Gateway: [README_AI_AGENT.md](../README_AI_AGENT.md)

## 1. What you get

| File in `obsidian-out/` | Generated from | Shows |
|---|---|---|
| `Board.md` | `docs/list-task-project.md` | Kanban board (Kanban plugin): Backlog · Todo · Doing · Review · Blocked · Done |
| `Home.md` | both | Counts per status, blocked tasks, sessions waiting for human review |
| `Agent Log.md` | `agent-history/entries/*.json` | Timeline of every AI session, newest first, in WIB |
| `tasks/PSI-###.md` | both | One note per task: fields, acceptance, dependencies, every AI run on it |
| `history/<id>.md` | `agent-history/entries/<id>.json` | One note per session: intent, outcome, changes, decisions, verification, follow-ups |
| `graph/` | graphify (optional) | Code-graph notes, see §7 |

Every card links to its task note, every task note links to its session notes, so the vault is the "what did the AI do on this?" view of the project, across both agents: card owners read `agent:claude-code` or `agent:hermes`, and the Agent Log shows which harness and model ran each session.

## 2. The one-way rule

```
docs/list-task-project.md ──┐
                            ├──▶ scripts/obsidian-sync.ts ──▶ obsidian-out/   (generated, read-only)
agent-history/entries/*.json┘
```

- **Sources are the truth.** To move a card, change its `status:` line in `docs/list-task-project.md`; the watcher redraws the board in about a second.
- **Never edit `obsidian-out/`.** Each run overwrites it. Dragging a card in Obsidian changes nothing real and is reverted on the next sync.
- **Why one-way:** agents and humans already edit the task file through git; letting the Kanban plugin write back would create a second writer that rewrites the whole file on every drag, and merge conflicts with agent branches would follow.

## 3. Setup (once per machine)

1. Install Obsidian.
2. `bun run obsidian:sync` (creates `obsidian-out/` content).
3. Obsidian → **Open folder as vault** → choose `obsidian-out/`.
4. Settings → Community plugins → turn off Restricted mode → Browse → **Kanban** → Install → Enable.
5. Open `Board.md`. It renders as a board because the file starts with the `kanban-plugin: board` frontmatter. If it shows raw Markdown, use the "Open as kanban board" command.
6. Optional: install **Dataview** to query session notes (§6).

## 4. Running the sync

`package.json` scripts (PSI-006):

```json
{
  "obsidian:sync": "bun scripts/obsidian-sync.ts",
  "obsidian:watch": "bun scripts/obsidian-sync.ts --watch",
  "agent:context": "bun scripts/agent-context.ts",
  "agent:check": "bun scripts/obsidian-sync.ts --check && bun scripts/agent-context.ts --check"
}
```

Dev dependencies: `bun add -d ajv ajv-formats` (JSON Schema 2020-12 validation of history entries).

| Command | Behaviour |
|---|---|
| `bun run obsidian:sync` | Validate, regenerate once, report warnings. Invalid history entries are skipped, never rendered |
| `bun run obsidian:watch` | Same, then re-run ~300 ms after any change in `docs/` or `agent-history/entries/`. Keep it open in a terminal tab next to `bun run dev` for a realtime board |
| `bun run agent:check` | Validate only; exit code 1 on any error (also fails when `.hermes.md` is stale, see [agent-operations/hermes.md](agent-operations/hermes.md#2-project-context-hermesmd)). Used by agents (contract C-16), the pre-commit hook (PSI-007) and CI |

What `--check` validates:

- Task blocks: known `status` and `area`, well-formed `owner`, no duplicate IDs, no `depends` pointing at unknown IDs.
- History entries: valid JSON, valid against `agent-history/schema.json`, file name equals `id`, `task_ids` exist in the task list, `supersedes` points at an existing entry.

Files are written only when their content changes, so Obsidian doesn't flicker or lose your scroll position.

## 5. Output formats

**Board card** (one per task):

```
- [ ] [[tasks/PSI-032|PSI-032]] Edge Function send-role-mail · agent:claude-code · 2 runs #backend #phase-3
```

The Done lane starts with the plugin's `**Complete**` marker and uses `- [x]` cards. The file ends with the plugin's settings block (`%% kanban:settings … %%`).

**Session note** (`history/<id>.md`) frontmatter, ready for Dataview:

```yaml
---
id: "2026-10-02T07-15-00Z__PSI-032__claude-code"
tasks: ["PSI-032"]
agent: "claude-code"
model: "claude-sonnet-5"
operator: "ficana"
outcome: "partial"
started: "2026-10-02T07:15:00Z"
human_review: true
---
```

## 6. Useful Dataview queries

Put these in any note of your own **outside** `obsidian-out/` (for example a personal vault that includes it), or paste them into Obsidian's search.

````
```dataview
TABLE outcome, agent, started
FROM "history"
WHERE human_review = true
SORT started DESC
```
````

````
```dataview
TABLE length(rows) AS sessions
FROM "history"
GROUP BY agent
```
````

## 7. Graphify notes in the same vault

graphify can write its knowledge graph as Obsidian notes into a sub-folder of this vault without touching our files:

```
/graphify . --obsidian --obsidian-dir obsidian-out/graph      # run inside Claude Code (graphify skill)
```

The sync script never deletes `obsidian-out/graph/`. See [graphify-architecture/README.md](graphify-architecture/README.md).

## 8. Git policy

`obsidian-out/` is a build artefact. Only its README is committed:

```gitignore
# .gitignore
obsidian-out/*
!obsidian-out/README.md
```

`.obsidian/` (your vault settings, installed plugins) stays local too; each person installs the Kanban plugin once.

## 9. Troubleshooting

| Symptom | Fix |
|---|---|
| Board shows raw Markdown | Kanban plugin disabled, or open `Board.md` with "Open as kanban board" |
| A task is missing from the board | Its block is malformed; run `bun run agent:check` and fix the reported line |
| A session is missing from the log | The entry failed validation; `agent:check` prints the schema error |
| Board doesn't update while editing | The watcher isn't running (`bun run obsidian:watch`), or you edited `obsidian-out/` instead of the source |
| Card moved in Obsidian jumped back | Expected: the board is read-only; change `status:` in the task file |
