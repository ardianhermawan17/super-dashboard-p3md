## 3. Key Decisions & Rationale

| Decision | Rationale | Alternatives Considered |
|---|---|---|
| Docs live under `docs/`; `README.md` + `README_AI_AGENT.md` stay at the repo root | The gateway links every doc from the root; the root stays readable | Every file at the repo root |
| Split docs into `frontend-architecture/`, `backend-architecture/`, `database-architecture/` | With Supabase most backend logic and **all** authorization are SQL, which has its own immutable-migration rules, review gates and pgTAP tests | One `backend-architecture/` folder |
| `agent-history/entries/` = **one JSON file per session** | Parallel branches and agents never conflict; append-only audit trail | Single append-only JSONL log; entries embedded in Markdown |
| **Contract v1.1** harness-neutral: Claude Code = builder, Hermes = operator | ECC is stable on Claude Code and minimal on Hermes; Hermes adds always-on chat, cron, persistent memory, any model provider | Both agents identical; Hermes only |
| Generate `.hermes.md` from `README_AI_AGENT.md` + `AGENTS.md` | Hermes loads only one context file and does not expand `@` imports | Hand-maintained `.hermes.md`; pointer line only |
| Obsidian sync is **one-way** (task list/history → `obsidian-out/`) | Avoids a second writer to the task list and merge conflicts with agent branches | Two-way sync with the Kanban plugin as editor |
