# List task project

> Source of truth for **what** gets built and **who** is on it. The Obsidian board is generated from this file ([integrated-obsidian-local.md](integrated-obsidian-local.md)); what was actually done lives in [historical-agent-work.md](historical-agent-work.md). Gateway: [README_AI_AGENT.md](../README_AI_AGENT.md).

## How this file works

Every task is an `###` heading followed by `- key: value` lines. `scripts/obsidian-sync.ts` parses exactly this shape, so keep it exact:

```
### PSI-999 · Example title (verb + object)
- status: todo
- area: backend
- owner: unassigned
- depends: PSI-030, PSI-031
- accept: One sentence (or several separated by ";") a reviewer can verify.
```

| Key | Allowed values |
|---|---|
| `status` | `backlog` · `todo` · `doing` · `review` · `blocked` · `done` |
| `area` | `repo` · `docs` · `agent-ops` · `frontend` · `backend` · `db` · `integration` · `infra` · `security` |
| `owner` | `unassigned` · `human` · `human:<name>` · `agent:<name>` (e.g. `agent:claude-code`, `agent:hermes`) |
| `depends` | Comma-separated task IDs, or `—` |
| `accept` | Acceptance criteria. `done` means all of them are met |

**Editing rules**
- Agents change only `status` and `owner` lines (contract C-03). Agents never set `done`; a human does after merge.
- New task → append under the right phase with the next free ID and `status: backlog`. Once this file is committed, IDs are never reused or renumbered.
- A task needing a human decision gets `status: blocked`; the reason goes in the session's history entry.
- `bun run agent:check` validates this file (duplicate IDs, unknown statuses or areas, dangling `depends`).
